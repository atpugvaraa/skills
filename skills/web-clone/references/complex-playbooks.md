# Playbooks for complex sites

## L4: animated brand site

Capture three responsive widths and identify scroll libraries, video, and Canvas usage. Break the page into hero, scroll storytelling, masks, hover states, and transitions. Prioritize rhythm and visual grammar, then compare key scroll positions. Report approximations instead of hiding them.

## L5: WebGL, Canvas, and Three.js

Find public source and source maps first. Record canvas dimensions, render framework, shaders, post-processing, physics, interaction, audio, and resource loading. Build a minimal runnable scene and add complexity one layer at a time. Verify interactions with real browser operations or video/screenshot evidence.

## L6: SaaS, ecommerce, and login-based systems

Limit work to authorized presentation and demo flows. Classify APIs as content, search/filtering, user state, or transactions/writes. Public content can use local fixtures; transactional APIs should be mocked with explicit success and failure states. Preserve loading, empty, error, and permission-denied states.

## Multi-page and CMS sites

Map navigation, footer, sitemap, and representative templates first: home, list, detail, search/filter, and contact. Generate repeated content from data. Do not attempt to clone the CMS backend.

## Completion evidence

Keep original recon, screenshots, route maps, interaction evidence, and asset/network inventories as applicable. Run locally and record console/page errors. Report structural, visual, interaction, responsive, and functional boundaries, including anything that could not be verified.
