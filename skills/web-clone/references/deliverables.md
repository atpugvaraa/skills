# Deliverables

## NOTES.md

Record the original URL, source repository, author, license and attribution; framework and runtime; complexity and clone mode; high-fidelity, approximate, and excluded parts; main risks; run commands; changes from the original; an original-versus-clone table; a replacement map; verification evidence; and anything that could not be verified.

## TEARDOWN.md for complex interactive work

Organize findings by rendering, compositing, physics, interaction, audio, and resource loading. Cite source file and line locations where available, and tag each key claim SOURCE, PARTIAL, or GUESS. If an AI analysis exists, compare its claims against real evidence. Separate transferable patterns from details specific to the target.

## RECON artifacts

Keep recon JSON and screenshots at desktop/tablet/mobile widths. Multi-page sites should retain route maps; interactive sites should retain interaction evidence; API-backed work should retain an authorized network inventory and fixtures; complex rendering work should retain source-map findings and a baseline capture.

## CLONE_REPORT.md and CLONE_AUDIT.md

When evaluating or sharing a result, report complexity, mode, fidelity evidence, known gaps, and next steps. Before deployment, audit tracking scripts, original branding, TODOs, external URLs, and recorded asset/license risks. A report is only as strong as its cited evidence.
